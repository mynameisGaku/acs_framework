# 実行時契約

この文書は、acs_framework の公開実行時APIに共通する既定の契約を定める正本です。
各機能フォルダーのREADMEは固有の条件を追加できますが、ここに反する場合は、そのAPIの宣言直前で
理由と異なる契約を明記します。何も書かれていない場合は、この文書を適用します。

## 失敗の返し方

予想できる失敗を例外やログだけで伝えません。呼び出し側が分岐できる値として返します。

| 戻り値 | 用途 | 失敗時 |
|---|---|---|
| `bool` | 成功したかだけが必要な更新 | `false`。対象と出力を変更しない |
| ポインター・ハンドル | 生成または検索 | `nullptr`または無効値。半端な登録を残さない |
| 結果struct・エラーenum | 理由、件数、再試行可否が必要 | 明示した失敗値と、成功時だけ有効な出力を返す |
| `void` | 失敗しない処理、または明記した最善努力 | 呼び出し側の成功判定には使わせない |

実装順は「入力検証 → 候補を作る → 全条件の成功後に反映」です。複数登録をまとめる処理は、途中で
失敗したら逆順に巻き戻します。出力引数は候補へ読み、成功時だけ代入します。失敗後に前の値を失う
APIや、「見えるが当たらない」のような半端な成功を新設しません。

`Source`の実行時APIは、入力不足、未接続、未検出、容量不足など予想できる状態を例外へしません。
別の対応が必要な失敗理由が2種類以上ある場合は、`bool`を増やすのではなく結果structまたはエラー
enumを使います。単なる計算失敗はログを出さず、結果を受け取る境界が必要に応じて一度だけ記録します。

## ログ

FrameworkのログはACSの`ACS_LOG_INFO`と`ACS_LOG_WARN`へ集約します。

- `INFO`: 起動時に一度だけ知りたい接続先、選択した置き場、初期化完了など。
- `WARN`: 無描画、無音、素材欠落、未接続、巻き戻し失敗など、処理は続くが開発者の対応が要る状態。
- 戻り値だけで通常分岐できる未検出、範囲外、入力取消は、毎更新のログを出しません。
- 同じ失敗を下層と場面境界の両方で記録しません。素材名や対象機能を説明できる境界を一つ選びます。
- 文頭へ機能名を置き、日本語で「何ができなかったか」と「どう続けるか」を書きます。

ゲームを安全に続けられない起動失敗は、警告を増やして続行せず、起動結果を失敗として返します。
新しいログ段階が必要になった場合は、個別機能で独自のログ機能を作らず、この方針とACS側の窓口を先に
更新します。

## スレッド安全性

明記が無いFramework実行時APIは、ゲームの主スレッドだけから呼びます。場面、ノード、部品、
subsystem、描画、入力、音、素材、保存、デバッグUIはこの既定に含まれます。`const`関数でも、
参照先のACS資源や内部キャッシュが共有されるため、スレッド安全を意味しません。

複数スレッドから呼べるのは、宣言直前に「スレッド安全」と明記したAPIだけです。入力と出力が値だけで、
共有可変状態、静的キャッシュ、ファイル、ACSオブジェクトへ触れない純粋計算は再入可能にできます。その場合も、
同じ出力先を複数スレッドで共有する責任は呼び出し側にあります。コールバックは登録元ではなく、コールバックを
実行する`Update`または呼出し元と同じスレッドで動きます。

Frameworkは現在、直接バックグラウンドスレッドを生成しません。新設する場合は、次を同じ変更で揃えます。

1. スレッドの所有者、開始条件、終了待ち、取消方法を明示する。
2. 主スレッドへ渡す値を候補として分離し、成功した結果だけを主スレッドで反映する。
3. 場面終了とアプリ終了でコールバック先や借用ポインターを残さない。
4. この文書と`Tools/RunRepoChecks.ps1`の監査例外を、理由付きで更新する。

## セーブ互換性

永続データは、書き手を最新版に一つだけ置き、読み手が対応済みの旧版を明示的に扱います。版が違う
データを現在の型として黙って読み替えません。壊れた入力や未対応版では、現在のゲーム状態と出力を
変更しません。

| データ | 現在の契約 | 用途 |
|---|---|---|
| セーブ枠 (`FSaveSlotStore`) | 呼出し側が渡す版と一致する型だけを読む | プレイヤー進行・設定 |
| シーンスナップショット | Framework envelope v1と従来ACS v2/v3/v4生データを読む | ノード木と名前 |
| リプレイ・シミュレーションスナップショット | 各形式の現在版だけを読む | 再現、試験、デバッグ |

セーブstructを変更する場合は、旧structを読み込める間は残し、`GetSlotInfo().Version`で分岐します。
旧値を一時候補へ読み、変換と検証が全て成功してから現在値へ反映します。最新版での再保存は移行成功後
だけに行い、失敗時は旧ファイルを残します。対応を打ち切る旧版は、v1.0.0以降の破壊的変更規則に従い、
変更履歴と移行方法へ明記します。

ファイル置換はACSの`CSaveArchive`またはFrameworkの`CAcsArchiveFile`を使います。一時ファイルから
差し替える安全性を失うため、対象ファイルへの直接上書きを新設しません。形式変更には、最新版の往復、
対応する最古版の読込、未対応版、破損、読込失敗時の出力不変を検証する回帰テストを付けます。

## 変更時の確認

- 公開コメントに入力、成功出力、失敗条件が書かれているか。
- 失敗前後でノード、登録、出力、保存ファイルが半端に変わらないか。
- 同じ失敗を複数層から記録せず、毎更新のログになっていないか。
- 主スレッド以外から呼べると誤解させるAPIになっていないか。
- 永続形式の版、旧版読込、移行失敗時の保持をテストしたか。
- Debug / Releaseテスト、`Tools/RunRepoChecks.ps1`、必要な実行確認を通したか。
