# Assets/Model3D — `Assets` に置いた FBX を取り込む

## 使う

```cpp
CModelLibrary Models;
Models.Bind( Application.GetAssets() );

FModel3DSpawnParams Params =
    FModel3DSpawnParams::FromMesh( FStringView( "Models/Robot.fbx" ), FVec3{ 0, 0, 0 } );
CModel3DSpawner::SpawnInto( Root(), Params, Models );
```

パスは **`Assets` からの相対**。

## なぜ «読む» が要るのか

`AMeshComponent3D::SetMeshPath` は**パスを覚えるだけ**で、読み込みはしない。パスを入れた
だけのノードを置くと、**何も出ないノード**ができる。しかも何のエラーも出ない。

置き場から読んでノードへ結び付けるまでを 1 呼び出しにしたのがこの層。

読めなかったら**置かずに** `nullptr` を返す。置いてから「出ない」と悩むより早く気付ける。
理由は必ず 1 行残る (ファイルが無い / 形式が違う / 置き場が見つからない)。

## この層が足しているもの

読み込み自体は ACS が持っている。**FBX の解釈も ACS の `CFbxAssetLoader` (ufbx)。**
二重読み込みの防止も `CAssetRegistry` がパスで覚えているので、同じモデルを 100 個置いても
読むのは 1 回。ここでは何も覚えない。

足しているのは 3 つだけ。

1. `Assets` からの相対名で書けるようにする
2. 対応していない拡張子を**置く前に**弾く (「読めないのか、置き場に無いのか」を混ぜない)
3. 読めなかった理由を 1 行残す

## 置き場の見つけ方

`CAssetRoot` が上から順に見る。1 度だけ調べて覚える。

1. 環境変数 `ACSFW_ASSETS`
2. いま居るフォルダの `Assets`
3. 実行ファイルの隣の `Assets`
4. 実行ファイルから**上へ辿って**最初に見つかった `Assets` (最大 8 段)

4 が要るのは、実行ファイルが `x64\Release` に出るため。**IDE から実行しても、出来上がりを
直接叩いても、素材をコピーせずに同じように動く。**

## 受け付けないもの

- `..` を含むパス、絶対パス。置き場の外を指せると、**配る段になって「自分の機械にしか無い
  ファイル」を掴んでいた**ことに気付く
- `.fbx` `.gltf` `.glb` `.obj` 以外。ACS 側にローダが無い

## 落とし穴

- **単位**。FBX をセンチメートルで書き出すと 100 倍で置かれる。カメラ・影・遮蔽の半径が
  全部その大きさに引きずられ、「置いたのに何も見えない」になる
- `Scale` で辻褄を合わせない。当たり判定と影がずれたままになる。書き出し側を直す
- 置き場が見つからないときは起動時に 1 行警告が出る。**黙って「モデルが出ない」にはしない**
