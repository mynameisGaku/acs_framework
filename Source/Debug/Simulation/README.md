# Debug/Simulation

`AcsFramework_Core/Simulation` を**見る側・操作する側**。開発中の道具。

このファイルは**フォルダに何を置いてよいか**を決めるもの。迷ったらここに戻ること。

---

## なぜ Core ではなくここにあるか

記録と再生の仕組みそのものは Core が持つ。ゲームの出荷物に要るのはそちらだけで、
**画面から操作する部分は開発中しか要らない**。

依存の向きも理由になる。`Debug` は `Core` を知ってよいが、`Core` は `Debug` を知らない。
ページを Core へ置くと、Core が DebugTop に縛られる。

```
Debug/Simulation/View  ──▶  Core/Simulation
                       ──▶  Debug/DebugTop (ページの継承点)
```

---

## 何ができるか

| 見えるもの | 何が分かるか |
|---|---|
| Mode | Live / Recording / Replaying。規則が差さっていなければその旨 |
| Tick | 進んだステップ数と、ステップ間のどこに居るか |
| Tape | 記録されている変化の件数 / 最後のティック / 種 |
| Runtime | 溜まっているイベント数と、処理落ちで捨てた秒数 |

| できること | 使う場面 |
|---|---|
| StartRecording | これから再現したい操作を始める前に押す |
| StartReplay | いま持っているテープを最初から流す |
| StartLive | 記録も再生もしない状態へ戻す |
| SaveTape / LoadTape | **バグが出た直後に保存する。** 後から読んで再生する |

「バグが出た後にコードを書き足してビルドし直す」では間に合わない。出た瞬間に画面から
保存できることが要る、という一点のためにこのページがある。

---

## フォルダに置いてよいもの

| 置き場所 | 置いてよいもの |
|---|---|
| `View/` | DebugTop のページと行 |

**シミュレーションの仕組みはここへ置かない。** それは `Core/Simulation` の担当。ここは
数字を映して、Core の口を叩くだけにする。状態も持たない (毎フレーム Core から取り直す)。

---

## 使い方

アプリの起動時に、他のデバッグページと同じ場所で足す (`CAcsFrameworkApp::InitialScene`)。

```cpp
Overlay->GetHUD().AddEntity( NewObject<ASimulationPage>( FString( "Simulation" ), *Simulation ) );
```

---

## 気をつけること

- Seed は記録を始めるときにだけ使う。**再生はテープが覚えている種を使う** ので、
  ここの数字を変えても再生結果は変わらない。
- パスは実行ディレクトリからの相対でよい。**掘っていないフォルダを指すと保存に失敗する**
  (実際に踏んだ)。`Saved/Replay/` を先に作っておくこと。
- 規則が差さっていないと Mode の右に「規則なし」と出る。その状態では回しても何も起きない。
