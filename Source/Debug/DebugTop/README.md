# DebugTop

ゲーム中に被せて値をいじるデバッグメニュー。シーンを差し替えずに使える。

このファイルは**フォルダに何を置いてよいか**を決めるもの。迷ったらここに戻ること。

---

## 表示方式と所有者

| | シーンとして使う | 重ねて使う |
|---|---|---|
| 入口 | ゲーム側が所有する専用シーン | `CDebugTopOverlaySubsystem` |
| 画面 | メニューだけ | ゲームの上に被さる (下は透ける) |
| ゲーム | 動いていない (別のシーン) | 動いたまま。既定では出している間だけ止める |
| 向く場面 | 起動直後の入口。腰を据えて触る | 詰めの調整。いじった結果がその場で見える |

**重ねる側はシーンにしない。** エンジンは top のシーンしか描かないので、シーンで作ると
下のゲームが消える。ロード画面と同じく、自前の `CSpriteBatch` と `FRenderContext` を持ち、
アプリがシーンを描き終えた後に描く。

`CAcsFrameworkApp` が更新、表示中の時間停止、シーン後の描画を所有するため、ゲーム側は `Update` と `Draw` を直接呼ばない。

`GetHUD()` でメニューを組み立てるまでは、切替キーを受けずゲーム時間を止めない。

`CGame::GetRenderCtx()` はシーンを描き終えた時点で畳まれている。そのまま使うと落ちるので、
重ねる側は文脈を自前で組み立てること。

---

## 継承点 (利用者が触るのはここだけ)

このモジュールが外へ出しているのは 3 つ。**これらを継承したものは利用者側**であって、
モジュールの中には入らない (同梱の既製品だけは例外として `Builtin/` に置く)。

| 継承点 | 置き場所 | 継承して作るもの |
|---|---|---|
| `CDebugTopElement` | `Element/` | 独自の行の型 (色・グラフ以外に増やしたいとき) |
| `ADebugTopEntity` | `Page/` | 1 画面ぶんのページ。`OnBuild` で行を並べる |
| `ADebugTopHUD` | 直下 | メニュー全体。見出しや説明文の出し方を変えたいとき |

ゲーム固有の専用シーンと派生ページは、DebugTop モジュールの外にある機能フォルダーへ置く。
これらはモジュールを使う側であり、DebugTop 本体と同居させない。

## 層と、依存してよい向き

上の層は下の層を知ってよい。**下から上へは参照しない。**

```
             ┌─────────────────────────────┐
   入口 ───▶ │ DebugTopHUD (調停役)         │  ページ間を繋ぐ。ページ同士は互いを知らない
             └──────────────┬──────────────┘
                            ▼
             ┌─────────────────────────────┐
             │ Builtin/   同梱の既製ページ   │  = 継承点の利用者。中身は普通のページ
             └──────────────┬──────────────┘
                            ▼
   ┌──────────┬─────────────┴───────┬───────────┬──────────┐
   │ Page/    │ Service/            │ Settings/ │ Widget/  │
   │ ページ    │ ページを跨ぐ機能      │ 保存と復元 │ 部品      │
   └────┬─────┴──────────┬──────────┴─────┬─────┴────┬─────┘
        ▼                ▼                ▼          ▼
   ┌─────────┐     ┌──────────┐     ┌──────────┐
   │ Element/│     │ Render/  │     │ Input/   │
   │ 行の型   │     │ 描画の下請け│    │ 入力の受け皿│
   └─────────┘     └──────────┘     └──────────┘
```

### 各層の受け持ち

| フォルダ | 受け持つもの | 置いてはいけないもの |
|---|---|---|
| 直下 (`DebugTopHUD`) | ページの木、いま出しているページ、ページ間の橋渡し | 行の描画そのもの、特定ページの都合 |
| `Page/` | 行の木と、その上で働く係の取りまとめ (下の表) | どのページにどの行を置くか (それは利用者が決める) |
| `Element/` | 行の型と値。`GetValueText` / `OnDecide` / `OnLeftRight` で答えるだけ | 自分の描画、自分の当たり判定 (位置を知らないため) |
| ⤷ | 型ごとに 1 ファイル。`DebugTopElement.h` は基底、`DebugTopElementTypes.h` は小さな型だけ。全部要るなら `DebugTopElements.h` (傘) | 傘をモジュールの内側から include すること (要るものだけ名指しする) |
| `Widget/` | 自分の見た目と自分の入力だけを持つ部品 | メニューの構造を知ること (デリゲートで外から差してもらう) |
| `Input/` ⤷ | 押しっぱなしの連射は `FInputRepeat` (AcsFramework_Core) に任せる。キー・パッド・マウスで同じ触り心地にするため | 連射の間隔を各所で持ち直すこと |
| `Render/` | 文字・図形・色の面・フォント焼き | 何を描くかの判断 |
| `Input/` | 打ち込み・パッド・カーソル形状 | 打った結果をどう使うか |
| `Service/` | ページを跨ぐ機能 (検索・取り消し・フォルダの読み取り・ファイル選択) | 画面への描画 |
| `Settings/` | 値の保存と復元、保存形式 | メニューの見た目 |
| `Builtin/` | モジュールが同梱する既製ページ | 継承点そのもの |

### `Page/` の内訳

ページは「行の木を持ち、係に振り分ける」だけにする。時間を跨ぐ状態 (掴んでいる・打っている・
どこを選んでいる) は係が抱え、ページ本体には持たせない。

| クラス | 受け持つもの | 知らないこと |
|---|---|---|
| `ADebugTopEntity` | 行の木、可視行の平坦化、配置の決定、描画、係の取りまとめ | 連打の間隔、ドラッグ中かどうか |
| `CDebugTopRowScroller` | どの行を選び、どこから何行出すか。行ごとに違う高さの積み上げ | 何のキーが押されたか (「何行動かす」だけが来る) |
| `CDebugTopRowMouse` | 押下・ドラッグ・ホイールの振り分け、連打、ダブルクリック | 行の並べ方、描き方 (判定に使う矩形は描いた側から受け取る) |
| `CDebugTopValueEditor` | 値の打ち込みと、確定した文字の行き先 | 欄をどこに描くか (矩形は `SetFieldRect` で教わる) |

`CDebugTopRowMouse` は振り分け先 (スクローラ・色のパネル・打ち込み) を `Bind` で 1 度だけ
受け取る。ページと同じだけ生きるものなので、毎フレーム渡し直さない。

### 用意してある行の型 (`Element/`)

| 型 | 用途 |
|---|---|
| `CDebugTopElementInt` / `Float` | 数値。範囲を持てばスライダーが付き、欄へ直接打ち込める |
| `CDebugTopElementBool` | ON / OFF (チェックボックス) |
| `CDebugTopElementEnum` | 選択肢から 1 つ。`DebugTopAddEnumRow` で列挙型から自動生成できる |
| `CDebugTopElementString` / `Path` | 文字列。Path は決定するとダイアログが開く |
| `CDebugTopElementVec2/3/4` | ベクトル。畳むと要約、開くと X/Y/Z/W を個別に編集 |
| `CDebugTopElementColor` | 色。見本を押すと色を選ぶパネルが浮く |
| `CDebugTopElementIntArray` / `FloatArray` | 配列。開くと要素ごとに編集 |
| `CDebugTopElementGraph` | 値の推移を折れ線で見る |
| `CDebugTopElementWatch` | 値を見るだけ (触れない)。右カラムを毎フレーム作り直す |
| `CDebugTopElementAction` | 決定すると処理を走らせる |

「まとめて見たいが個別に触りたい」値は、**親が要約を出し、子が実体を持つ**作りにする
(色とベクトルが同じ形)。こうすると保存も成分ごとの数値としてそのまま乗る。

## 決めごと

- **行は自分を描かない。** 行は自分の表示位置を知らないので、描くのは `Page/` と直下だけ。
  行は文字列と値を返すことに徹する。
- **部品はメニューの構造を知らない。** 例えば検索欄 (`Widget/DebugTopSearchBox`) は
  「何を探すか」を `FDebugTopSearchCollector` で外から差してもらい、選ばれた候補は
  `ConsumeChosen()` で持ち主が引き取る。飛び先を決めるのは調停役の仕事。
- **値の取り出し / 書き戻しは 1 か所。** 種類ごとにどの口 (`TryGetFloat` 等) を使うかは
  `Element/DebugTopElementValue.h` が唯一の出どころ。保存 (`Settings/`) と取り消し
  (`Service/DebugTopHistory`) が別々に書くと、片方だけ対応した型で無言で食い違う。
- **同じ定数を 2 か所に置かない。** 色の面の割り当ては `Render/DebugTopColorField.h` が
  唯一の出どころで、当たり判定 (`Element/DebugTopElement.cpp` の `PickAt`) も同じものを使う。
  分けると「押した位置と出ている色が食い違う」形で無言でずれる。
- **新しいファイルを足したら** `Tools/Sync-ProjectFilters.ps1` を回して .vcxproj へ登録する。

## どこに足すか

| やりたいこと | 触る場所 |
|---|---|
| 行の種類を増やす | `Element/` に `CDebugTopElement` の派生を足し、`DebugTopElements.h` (傘) へ 1 行足す |
| ページを増やす | ゲーム側の機能フォルダーに `ADebugTopEntity` の派生を足す |
| 浮かせる UI を増やす | `Widget/` に部品を足し、`Page/` から持たせる |
| 保存形式を増やす | `Settings/` に `EDebugTopSettingsFormat` の分岐を足す |
| 値の型を増やす | `Element/DebugTopElementValue.cpp` の取り出し / 書き戻しにも足す (足さないと保存と取り消しから漏れる) |
| 決定キーの意味を変える | 行で `PrefersDecide()` を返す (打ち込める行でも `OnDecide` を優先できる) |
